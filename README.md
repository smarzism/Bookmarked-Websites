## What is this?

This is NOT a curated "best of" list. It is my personal bookmark board: sites I found useful, interesting, or want to try later. Some are tested, some are not yet. Your needs and experience level are different from mine, so treat it as a starting point, not a recommendation.

## What should I open first?

Don't be overwhelmed by the number of sites. Pick the category you care about and start with the ones marked **✅ Tested**. The live board lets you search by name, address or note and filter by category or status.

## Status badges

- **✅ Tested**: I have used the site and it works as described (`"approved": true`).
- **📝 To test**: on my list to try (`"todo": true`).
- No badge: bookmarked, not reviewed yet.

## Sorting

GitHub repositories come first. Categories appear in the same order as on the live board (the order they first appear in `sites.json`). Within a category, GitHub repositories are listed first, then the other sites, each in their `sites.json` order.

## Add a site

Edit `sites.json` and add an object with a unique `id`, `name`, `url`, `category` and `note` (each with `fa` and `en`), `approved` (`true` once you have tested the site) and `todo` (`true` if you still want to test it), then commit. On push:

- the **Deploy to GitHub Pages** workflow fetches the og:image and redeploys the board (it also refreshes images every Monday);
- the **Update README** workflow regenerates the tables above and commits the new README. Run `git pull` afterwards to get it locally.

To hide an entry without deleting it, comment out its lines with `//`.

## Setup

1. Create a GitHub repo. Name it `YOUR-USERNAME.github.io` to get `https://YOUR-USERNAME.github.io` as the address, or any other name to get `https://YOUR-USERNAME.github.io/REPO-NAME/`.
2. Put these files in the repo root and push to `main` (or `master`).
3. In the repo: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Open the **Actions** tab and wait for "Deploy to GitHub Pages" to finish.

## Notes

- If a site has no og:image, the card shows a colored letter instead.
- Images are downloaded at build time into `og/` (not committed), so the page never depends on other sites while loading.
- To test locally: `node scripts/fetch-og.mjs && npx serve .`
- To rebuild the README locally: `node scripts/build-readme.mjs`
